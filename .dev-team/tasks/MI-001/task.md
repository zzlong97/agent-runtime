## 负责人已确认的方向

1. 应用层多实例；PostgreSQL、Redis 和入口自身高可用另设阶段。
2. Runtime 多活，每个 Run 同时只有一个有效执行者。
3. 远程 Capability 统一入口、内部自治，Runtime 不管理其物理副本。
4. 依赖正常且有容量时，故障后 30 秒内开始合法恢复，业务完成时间另计。
5. Runtime 同构副本同时提供 API/执行器，以 PostgreSQL 调度，不增加独立消息队列。

上述方向及当前完整规划已获批准；实施范围明确从MI-DEV-01开始，不预先验收未来实现。

## 已批准实施拆分（当前仅启动MI-DEV-01）

1. MI-DEV-01：Run租约/Session屏障字段及部署契约的持久化、领取/续租原语、同连接
   Guarded Checkpointer与真实PostgreSQL探针；不替换普通服务分派或开启部分保护的多活。
2. MI-DEV-02：受控Checkpoint接入实际Parent/Child、Coordinator及Task/Ledger、事件和
   终态完整写入隔离；不以进程内锁或只检查顶层终态代替保护。
3. MI-DEV-03：跨实例 Cancel/Resume 与持久 Session 删除屏障。
4. MI-DEV-04：集群总并发、readiness 和优雅退出。
5. MI-DEV-05：多进程/容器部署与故障演练、回归和远程部署契约测试向量。

依赖、预期模块与完成证据见 architecture 18.9，不复制维护第二份详细架构。
