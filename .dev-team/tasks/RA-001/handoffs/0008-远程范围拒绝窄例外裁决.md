## 本次正式正文变化

- architecture 15.5：明确本地零Operation规则不变，远程仅引用17.3～17.5受控例外。
- architecture 17.3：合法拒绝须显式OUT_OF_SCOPE、同Task/context的已确认rejected终态、零公开输出/业务State/ChildCheckpoint；普通rejected仍是远程失败。服务端须在业务接受前拒绝，Runtime不得读取远程私有State证明零业务状态，改由受控契约及Fake/服务端测试验证。
- architecture 17.4：同事务锁定/复核归属和Operation集合，精确清理本次稳定messageId对应remote_send，恢复原current、删除provisional Task，并写Task回滚和Invocation rejected内部结果；不按key前缀批删。
- architecture 17.5：保留绑定/远程终态事件，沿既有内部事件/Sequencer串联清理结果；提交前后崩溃均幂等对账，不重新Send或新建远程任务，不新增表或公开事件。
- decisions D-056/D-067：增加日期、批准来源和窄例外边界，保留原决定及其他安全条件。
- requirements 7.5原文也明确“零Operation”，优先级高于architecture，故必须补9.2例外引用；9.2同步最小产品条件及正式架构/决策引用。其他需求及MI章节未改。

## RA-DEV-02 可直接纳入的范围与验收

0006的绑定/恢复/取消/删除路径建议仍有效；此次已批准条件解除**远程显式拒绝回滚**分支的裁决等待，可按更新正文直接开发，不重走需求/架构审批。
预期影响：remote Adapter控制结果、Invocation Gateway、TaskService/Task Repository的受控原子回滚、内部事件及恢复对账测试；不增加业务表、普通Capability SDK接口或通用Ledger删除API。

| 验证输入 | 必须得到的结果 |
| --- | --- |
| 确认同一远程Task/context终态rejected+显式码，零输出/业务状态/ChildCheckpoint，唯一对应Send行succeeded | 一次事务清理该传输行、恢复原current并删除临时Task；同事务保存Task回滚/Invocation rejected；绑定/远程终态证据仍在 |
| 同上，但本地崩溃使目标Send行仍pending、远程结果已经确认 | 可依该确定结果进入同一受控事务；不能将未知pending或未确认状态伪装成此情况 |
| 其他业务Operation、remote_cancel、其他消息Send、归属不符或未知pending | 整个窄例外回滚不执行；台账及Task不被部分清理，不能仅靠key前缀或改状态放行 |
| 缺显式码的普通rejected、输出/Artifact、业务State或ChildCheckpoint已推进 | 不作合法范围拒绝回滚，按已批准失败/未知结果边界处理；不得伪装unsupported |
| 任一事务步骤失败/提交前崩溃 | 行、current、Task、内部结果整体回滚；同ID重建Runtime可凭原绑定/终态继续对账 |
| 提交后、Parent接收rejected前崩溃 | 读取已回滚Task/关闭Invocation的既有结果，不再Send、不新建远程Task、不重复清理 |
| 同样的本地Capability拒绝且已有Operation | 继续按既有契约违规失败；不得命中远程例外 |

对应RA-AC-06/07及合法OUT_OF_SCOPE有限回流；仍需RA02单元和PostgreSQL原子性/重放验证。此次只更新文档，未声称这些新增用例通过，不替代RA03文本Interrupt探针或真实联调。
